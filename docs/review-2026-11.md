# pyGS review for biological GRN inference

22 November 2026. Review only: no inference code was changed.

Compared `main` with GeneSPIDER on Bitbucket (`sonnhammergrni/genespider`, master as of this date): `+Methods/lsco.m`, `lasso.m`, `ridgeco.m`, `elnet.m`, `LSCON.m`, `Zscore.m`, `GENIE3.m`, `TIGRESS.m`, `CLR.m`, `+Methods/@NestBoot/` (`NestBoot.m`, `lsco.m`, `lasso.m`), and `+datastruct` (`Dataset.m`, `noise.m`, `scalefree.m`, `stabilize.m`, `scdata.m`). The installed dependency checked was sparselink 1.3.0.

Left to other agents, and not repeated here: PR #4 (CLI flags, SNR_L on the menu, replicates, plot layout, a Z-score method, tier help), PR #5 (LASSO empty-fit crash, NestBoot ridge rewritten as RidgeCO), and the CI agent (workflow and per-method tests). Related gaps those PRs leave are marked below.

## Already aligned

These should not be “fixed” into something else.

- LSCO is \(A = -P\,Y^{+}\). `src/methods/lsco.py` calls sparselink, and sparselink’s `lsco` is `-P @ pinv(Y)`. That is `Methods/lsco.m` (`-data.P*pinv(response(data,net))`). A normalised zeta in \([0,1]\) is mapped onto the nonzero coefficient range the same way (`rawZeta = 0`).
- `pygs nestboot -m lsco --zeta` rescales \(Y\) with min–max onto \([-1,1]\) and cuts \(|A_{ij}| \le \zeta\). That matches `@NestBoot/lsco.m`, which sets `rawZeta = 1` and `data.Y = rescale(data.Y,-1,1)`.
- The NestBoot null permutes genes inside each sample. `src/methods/nestboot.py` (the `gene_order` draw) matches `Dataset.shuffle` and the loop in `@NestBoot/NestBoot.m`.
- \(G = -A^{+}\) in `src/datastruct/Network.py` is the GeneSPIDER static gain. `src/bench/snr_benchmark.py` simulates \(Y = -A^{+}P + E\) and scales \(E\) from the smallest singular value of the noise-free response over a chi-square noise level. That is the structure of `datastruct/noise.m` with `SNR_model = "SNR_L"`.
- `src/datastruct/stabilize.py` is a real port of the SDP in `datastruct/stabilize.m` (SCS instead of CVX). The benchmark generator does not call it; see item 5.
- sparselink’s `evaluate` drops the diagonal before AUROC, AUPR, F1 and MCC. The public `pygs evaluate` command does not; see the evaluation section.

## Top 5

1. **LASSO still is not GeneSPIDER’s perturbation lasso.** PR #5 stops the empty-fit crash and leaves one default penalty plus a cutoff. The MATLAB NestBoot method sweeps `Lambda` on the regression of \(-P_{i}\) on \(Y\), with MATLAB’s standardisation. Until that exists, K562 NestBoot LASSO is a different estimator from LSCO and from the paper.
2. **GENIE3 and TIGRESS are stored transposed relative to \(A\), and TIGRESS is not TIGRESS.** Gold networks and LSCO use row = target, column = regulator. Tree and stability scores are written the other way, then scored elementwise. Reported AUROC for those methods is the score of the transpose.
3. **The NestBoot bootstrap is not `Dataset.bootstrap`, and the FDR is not checked against known false edges.** GeneSPIDER forces one replicate of every perturbed gene, then fills the remaining columns. pyGS either resamples inside perturbation groups or draws columns until rank fails 100 times. Nothing in `tests/` compares the reported FDR with the fraction of false edges on a known \(A\).
4. **Perturb-seq and the single-cell simulator are missing.** An `.h5ad` file is read as cells × genes and given no design. NestBoot then invents \(P = I\). `datastruct/scdata.m` (negative binomial, clusters, dropout, fold-change versus counts) has no Python counterpart. That is the gap for K562 Perturb-seq, as distinct from the knockdown TSV the CLI already understands.
5. **The synthetic ensemble does not reproduce GeneSPIDER’s stability design, and one CLI path uses another dynamical model.** The SNR benchmark only builds low-interampatteness networks by shifting the diagonal. The interactive “GeneSpider model” uses \(Y = (I-A)^{-1}(P+\text{noise})\) and a variance ratio. High condition number, the hard half of the GeneSPIDER benchmark, cannot be requested.

## High

### 1. Perturbation LASSO / elastic net: zeta has to be the L1 penalty

**Problem.** Two LASSO paths, neither is `@NestBoot/lasso.m`.

On `pygs nestboot`, only LSCO receives \(P\) (`PERTURBATION_METHODS` in `src/bio/io.py`). LASSO is fit once at sparselink’s default `alpha=0.01`, predicting expression from expression, and `--zeta` is then a hard cutoff of that one matrix (`src/bench/cli.py`, `_infer` inside `_cmd_nestboot`). PR #5 documents this and leaves the penalty sweep open. The same block is what `elastic_net` and, on main, `ridge` go through. PR #5 rewrites the ridge arm as RidgeCO; the benchmark runner below is a separate path and is not that rewrite.

On `pygs bench`, `src/methods/lasso.py` does sweep a grid and does pass \(P\). The grid is `np.logspace(-6, -1, 30)` of sklearn `alpha`, or `ZETA = np.logspace(-6, 0, 30)` from `src/bench/snr_benchmark.py`. sklearn `Lasso` is `fit_intercept=False` and does not standardise columns. The target is \(+P_{i}\), not \(-P_{i}\).

`@NestBoot/lasso.m` is:

```matlab
b = lasso(response(bdata,net)', -bdata.P(i,:)', 'Lambda', zetavec, 'Alpha', 1);
Afit(i,:,:) = b;
```

MATLAB `lasso` standardises predictors and fits an intercept unless told not to. With `rawZeta = 0` it first finds the penalty that empties the network, then maps a user zeta in \([0,1]\) onto \([0, z_{\max}]\). The standalone `Methods/lasso.m` regresses \(+P_{i}\) instead of \(-P_{i}\). The NestBoot copy is the one that matches LSCO’s sign (\(A Y \approx -P\)). Elastic net is the same file with `Alpha < 1` (`Methods/elnet.m`). sparselink’s elastic net is the same sklearn-style loop as LASSO.

Signs feed NestBoot: a link’s sign is the majority of positive fits (`src/methods/nestboot.py`, `sign = np.where(2 * positive >= total, ...)`). A systematic sign flip versus LSCO changes `sxnet` even when the unsigned support is similar.

**Change.** One perturbation regression, shared by NestBoot and the benchmark: for each gene \(i\), L1 (and elastic net) of \(-P_{i}\) on \(Y\), MATLAB-compatible standardisation, zeta as `Lambda`. `rawZeta=0` should search \(z_{\max}\) the way `lasso.m` does, not assume `logspace` is already on that scale. Keep the PR #5 empty-stack behaviour when a penalty returns no edges. Add a fixture: on a tiny full-rank knockdown, the smallest-penalty LASSO should have a negative diagonal and the same sign pattern as LSCO up to shrinkage.

**Effort.** Medium. One fitter used by `src/methods/lasso.py` and `_cmd_nestboot`, plus a sign fixture. No new dependency if it stays on sklearn, but the alpha definition has to be written down next to MATLAB’s `Lambda`.

### 2. GENIE3 and TIGRESS: orientation and the TIGRESS algorithm

**Problem.** GeneSPIDER \(A_{ij}\) is the effect of gene \(j\) on gene \(i\) (column = regulator, row = target). The GeneSPIDER chapter in this repo says the same. LSCO and the gold matrices follow that.

sparselink 1.3.0 `GENIE3Method.fit` writes `A[mask, i] = rf.feature_importances_` with column \(i\) the target, so the entry is regulator × target. `TIGRESSMethod.fit` writes `A[mask, i] = counts / n_bootstrap` the same way. `src/methods/genie3.py` and `src/methods/tigress.py` threshold that matrix and return it. `src/bench/snr_benchmark.py` scores it with sparselink `evaluate` against \(A\) with no transpose. Directed AUROC/AUPR for these two methods answers “how well does \(A^{\top}\) rank the edges of \(A\)”.

`Methods/GENIE3.m` transposes the VIM before the cutoff (`Als = GENIE3(Y')' + eye`). `Methods/TIGRESS.m` calls the original routine with `R=1000`, `alpha=0.4`, `L=2` (1000 resamples, predictor randomisation 0.4, first 2 LARS steps) and stores `Network(edges(i,2), edges(i,1))`. The Python “TIGRESS” is 50 bootstraps of `LassoLarsIC` (BIC), no predictor randomisation and no step limit \(L\). That is closer to a BIC stability score than to Haury et al. or to the MATLAB wrapper. NestBoot refuses to wrap it (`NESTBOOT_EXCLUDED` in `src/bench/genespider.py`) for the right reason — it is already a bootstrap — but the direct score is still the wrong matrix and the wrong procedure.

CLR is symmetric, so this particular bug does not hit it. CLR has a different mismatch, under Medium.

**Change.** Pick one storage convention, the GeneSPIDER one, and transpose GENIE3 and TIGRESS at the pyGS boundary so every method that `evaluate` sees is target × regulator. Reimplement TIGRESS as stability selection with feature randomisation and a fixed number of LARS steps, defaulting to the MATLAB arguments (`R=1000`, `alpha=0.4`, `L=2`), and keep the BIC bootstrap only if it is named as its own method. A 6-gene fixture with one true edge \(i \leftarrow j\) should light that entry, not the reverse, for LSCO, GENIE3 and TIGRESS.

**Effort.** Medium for the transpose and the fixture. Medium again for a real TIGRESS; the algorithm is small, the test is the work.

### 3. NestBoot resampling, and FDR that is never checked on known edges

**Problem.** `@NestBoot/lsco.m` calls `bootstrap(data)`. `Dataset.bootstrap` (`+datastruct/@Dataset/Dataset.m`) does not draw a plain column bootstrap. For each gene it draws one existing perturbation of that gene, places those \(N\) columns first, and only then fills columns \(N+1 \ldots M\) by sampling any experiment. Every gene stays perturbed, so \(P\) stays full rank when the original design hits every gene.

`src/methods/nestboot.py` `run_nestboot` does one of two other things.

- `keep_design=False` (the SNR benchmark’s `nestboot_stack`): sample columns with replacement, and if \(P\) loses rank, redraw. After 100 failures in a row it stops checking and keeps rank-deficient draws. The comment says this is GeneSPIDER. The MATLAB routine does not give up, and it is not this sampler.
- `keep_design=True` (`pygs nestboot` when a knockdown design was detected): resample inside groups of identical \(P\) columns, preserving replicate counts. That keeps rank, and it is a reasonable design for two replicates, but it is not “one of each gene, then unrestricted extras”. With two replicates the MATLAB draw and this draw have different duplicate rates, so support and the null histogram move.

The gene-wise shuffle inside each sample is the right null (see above). `src/bench/snr_benchmark.py` `shuffle_genes` is a different null: it permutes experiments inside each gene. `--randomize` therefore does not reproduce the NestBoot null. PR #4 does not claim to change this.

FDR math in `_nested_fdr` follows the shape of `NB_FDR` / `FDRcutoff` in `@NestBoot/NestBoot.m`: bin support, trapezoid area of the upper tail, cutoff where shuffled area / measured area is at most the FDR, keep links whose minimum support across outer runs clears that cutoff. Two numerical differences are worth a fixture rather than a silent rewrite. MATLAB sets `support_cross = orig_index/100`, hardcoded for 100 outer runs; Python uses `cut_bin / n_outer`, which is the right generalisation and should stay. MATLAB multiplies the input FDR by 100 and divides again inside `FDRcutoff`; Python compares the ratio to `fdr` directly. Failed fits are counted as empty networks (`src/methods/nestboot.py`, the `failures` path), which lowers measured support and pushes the cutoff up.

No test compares that cutoff with the empirical false-discovery fraction on a network whose \(A\) is known. `tests/test_nestboot_support_table.py` only checks that `fdr_curve` has a shape. For a method whose claim is FDR control, that is the missing experiment. Synthetic runs where the truth is known are exactly the place to do it.

**Change.** Make the default resampler the MATLAB one: one sampled replicate of every perturbed gene, then a plain draw for the extra columns. Keep `keep_design` as an explicit option for designs where dropping a gene is unacceptable, and name it as such in the help. Retry failed fits or drop them from the denominator instead of scoring them as empty. Add one calibration test: several small stable networks, a few SNR_L values, LSCO NestBoot at nominal FDR 0.05, and a table of empirical FDR (false edges among edges that pass) versus 0.05. Do not treat a single seed as a proof; report the distribution.

**Effort.** Medium for the sampler and the rank policy. Medium for the calibration harness. The harness is the one that tells you whether items 1–3 are done.

### 4. Single-cell and Perturb-seq

**Problem.** The maintainer’s K562 data arrives as a knockdown table and as Perturb-seq. The table path works: `src/bio/io.py` builds \(P = -1\) when column names are gene names, which is the sign LSCO wants for a negative diagonal. QC in `src/bio/knockdown.py` (dropout fill from replicates, own-gene z, per-gene scaling) is aimed at that table.

`.h5ad` does not build a design. `load_inference_inputs` returns `P = None`. `_cmd_nestboot` then sets `ds._P = np.eye(n_genes, n_samples)` (`src/bench/cli.py`). For a cell × gene AnnData matrix that identity says the first \(N\) cells are one-gene knockdowns of genes \(1 \ldots N\) and the rest are unperturbed. LSCO will fit that fiction. There is no read of `obs` columns such as guide, target gene, or control, no pseudobulk by target, and no split of control cells from perturbed cells.

`datastruct/scdata.m` is the toolbox’s single-cell generator: static-gain fold changes, negative-binomial pseudocontrol, cluster structure, log-count conversion, dropout. Nothing under `src/datastruct/` or `src/bench/` implements it. `src/bio/preprocessing.py` can transpose an `.h5ad` and optionally restrict to a TF list; it does not attach a perturbation. GRNBoost2 is vendored under `src/methods/_vendor/arboreto/` and is only reached if SCENIC+ is started with `use_arboreto=True` (`src/methods/scenicplus.py`). It is not a `pygs` method.

PR #4’s Z-score is the right cheap baseline for a knockdown design. It does not fill this gap. `Methods/Zscore.m` standardises each gene by its mean and standard deviation over all experiments, and stores `Zsc(affected, perturbed)`. PR #4’s description uses the experiments in which that gene was not perturbed as the background. Those two z-scores differ once the perturbation moves the mean. Worth aligning with `Zscore.m` if the goal is the toolbox method, or labelling the complement-based score as the DREAM variant if that is intentional.

**Change.** For AnnData, require a target column and build \(P\) from it (control cells as zero columns, or pseudobulk per target with an explicit count of cells). Refuse to invent \(P = I\) when the sample count is not the design. Add `scdata`: the MATLAB arguments (`SNR`, dispersion, cluster count, log base, dropout) on top of the existing \(Y = -A^{+}P + E\) simulator. Register GRNBoost2 as a method that returns target × regulator, since arboreto is already in the tree. A pseudobulk-per-guide helper is the piece that makes K562 Perturb-seq usable in NestBoot without a hand-built TSV.

**Effort.** Medium for “read the guide column, build \(P\), never invent \(I\)”. Large for a faithful `scdata` plus a GRNBoost2 registration and a pseudobulk helper. The design-matrix refusal is the part that prevents a wrong network; do that first.

### 5. Stability, condition number, and which equation generates \(Y\)

**Problem.** GeneSPIDER’s point is to vary interampatteness. `datastruct/stabilize.m` documents low as \(\mathrm{cond}(A) < N/2\) and high as \(\mathrm{cond}(A) > 2N\), and solves an SDP on the symmetric part so the edge pattern stays put. `src/datastruct/stabilize.py` copies that SDP. The generator the benchmark actually runs does not use it.

`stable_network` in `src/bench/snr_benchmark.py` takes a sparselink support, draws i.i.d. Gaussian weights, and shifts the diagonal until the symmetric part is negative definite and `cond(A) <= N/2`. Every simulated network is low-IAA. The shift often dominates the off-diagonal weights, so the network is nearly a set of independent genes and inference looks easier than the toolbox’s high-IAA suite. There is no high-IAA switch. `src/datastruct/scalefree.py` is a preferential-attachment port with diagonal \(-1\) and no stability step; the benchmark does not call it. `src/datastruct/smallworld.py` and `src/datastruct/rss.py` are empty files. Docs that import `datastruct.smallworld` (`docs/old/`) do not run.

A second model is labelled as GeneSPIDER and is not. `_infer_from_synthetic` and `_synthetic_guide` in `src/bench/cli.py` use

```text
Y = (I - A)^{-1} (P + noise),   noise std = sqrt(var(GP) / SNR)
```

with `SNR` defaulting to 1000. sparselink’s `generate_data` is the same structural equation with zero diagonal and spectral radius 0.8. GeneSPIDER is \(Y = -A^{-1}P + E\) with degradation inside \(A\). PR #4 retargets the menu SNR number onto SNR_L; this equation is a different object, and it is still what those two functions implement on `main`.

`Dataset.populate` sets `Y = A @ P` when constructed from a network (`src/datastruct/Dataset.py`). `true_response` then correctly returns \(G P\). `tests/datastruct/test_dataset.py` locks the wrong assignment in (`# Y = A @ P`). `Experiment.gaussian` adds `scale * randn` and never calls the chi-square SNR.

Smaller SNR constant: `Dataset.get.SNR_L` uses \(\alpha = 0.01\) (`chi2inv(0.99, numel(P))`). `noise.m` uses `analyse.Data.alpha`. Python `CHI_ALPHA = 0.95`. For \(N \ge 50\) the noise standard deviation differs by about a percent; for \(N=10\) by a few percent. Not the main error, but a stored file’s `SNR_L` and a Python simulation asked for the same number are not the same noise level.

**Change.** Build benchmark networks with the SDP (or an equivalent weight scaling) at low and high IAA, and record `cond(A)`. Point the interactive generator at `simulate_expression` so there is one equation. Either make `Dataset(network)` store \(GP\), or stop constructing \(Y\) there and let the test expect `None` until noise is applied. Implement `smallworld` or stop exporting the module. Set the chi-square tail to 0.99 when the claim is “the SNR_L stored in GeneSPIDER files”.

**Effort.** Medium for wiring `stabilize` into `stable_network` and adding a high-IAA option. Small for deleting the \((I-A)^{-1}\) path in the CLI and for the chi-square constant. Small for `Dataset.populate`, but it is a behaviour change of a tested helper.

## Medium

### Evaluation: unsigned, oracle sparsity, two diagonal policies

**Problem.** sparselink `evaluate` (used by the SNR benchmark) masks the diagonal, then reports threshold-free AUROC and AUPR of \(|A|\), and the best F1 and the best MCC over a second threshold sweep of that same matrix. `comparison_rows` in `src/bench/snr_benchmark.py` then keeps, per method, the zeta with the best F1. The number is an oracle over zeta and over a further cutoff. That can be a legitimate “best achievable on this grid” curve; it is not an operating point a biologist can set before seeing \(A\). The menu benchmark (`_fit_best` in `src/bench/genespider.py`) goes further and picks the alpha with the best AUROC on the true network, so the reported AUROC is the maximum over the grid.

`pygs evaluate` calls `src/bio/evaluation.py`, which does not mask the diagonal. GeneSPIDER diagonals are structural and nonzero. A method that estimates them (LSCO) picks up \(N\) easy true positives. `src/analyze/CompareModels.py` does the same. Neither reports sign agreement. A repression predicted as an activation counts as a true edge. Direction error (the transpose) is invisible except as a mild AUROC drop. \(R^{2}\) compares absolute weights with no scale match, so it is not a reconstruction error for \(A\).

There is no biological gold standard in the benchmark: RegulonDB, DREAM5, TRRUST/ChIP, or a K562 Perturb-seq target set. Stored GeneSPIDER JSON is synthetic. Real-data runs produce an FDR and a support table, not a precision against an external network.

**Change.** One scoring function: diagonal off, unsigned AUROC/AUPR, plus signed scores (sign accuracy on the true edges, and a signed AUPR that treats a wrong sign as a non-edge). Publish the full zeta curve and, separately, any “best F1” number with that label. Stop selecting alpha by test-set AUROC in `_fit_best`. Add one real-network benchmark even if the gold standard is incomplete, and say what the positives are (ChIP, motif, or a curated knockdown response).

**Effort.** Small for the diagonal and the sign metrics. Medium for a real-data benchmark with an explicit positive set.

### CLR, Z-score background, LSCON, Bolasso

**Problem.** `Methods/CLR.m` tells the user to run `clr(Y, 'stouffer', 10, 3)` on GeneSPIDER data (no transpose) and `'rayleigh'` on DREAM4. sparselink CLR is equal-frequency binning (at most 10 bins) and the Faith score \(\sqrt{z_i^{2}+z_j^{2}}\). That is a different combination rule. Rank-bin mutual information is also a pure Python double loop, which is why CLR does not scale (see Performance).

`Methods/LSCON.m` is LSCO followed by column normalisation \(\tilde A_{:j} = N A_{:j} / \|A_{:j}\|_1\), then the same zeta cut. It is absent. Bolasso is the method the NestBoot LASSO file is still commented as; the toolbox’s stability-selection LASSO (intersection of supports across bootstraps at a fixed lambda) is not in pyGS. TIGRESS is not a substitute, for the reasons in item 2. The LESSHUB branch of GeneSPIDER (truncated SVD in place of `pinv` when singular values are small) is not on master and not here; it matters at low SNR_L, where `pinv` follows noise.

PR #4’s Z-score background is the non-perturbed experiments. `Methods/Zscore.m` uses the mean and standard deviation of each gene across every experiment, written at `(affected gene, perturbed gene)`. Confirm which one landed, and name it in the help.

**Change.** Add a Stouffer CLR option and use it as the GeneSPIDER default. Add LSCON as a flag on LSCO (column \(\ell_1\) normalisation before the cut). Bolasso is “LASSO at one lambda, keep edges selected in at least a fraction of bootstraps”; it falls out of item 1 once the penalty is real. A truncated-SVD LSCO can wait until the FDR calibration shows LSCO falling apart at low SNR.

**Effort.** Small for LSCON and for labelling the z-score. Medium for Stouffer CLR. Bolasso is small once LASSO is a penalty sweep.

### Priors and direction helpers

**Problem.** `src/methods/prior_lasso.py` lowers a single sklearn alpha for a whole target to the minimum prior-adjusted alpha, then returns `np.abs(A)`. It is not registered in `src/methods/__init__.py` `run`. That is not Inferelator (TF activity, prior-weighted penalties per coefficient, signed output). `src/bio/preprocessing.py` `format_regulons` reads `adjacency[i, j]` as TF \(i\) → target \(j\). For an LSCO matrix that entry is the effect of \(j\) on \(i\), so the edge list is transposed for every perturbation method. `src/bio/direction.py` `infer_direction` solves \((I-A)^{-1}P\) and indexes columns with `i % n_experiments`. The `--directed` flag calls it. On a knockdown design whose columns are replicates, that index is not “the perturbation of gene \(i\)”.

**Change.** Either implement a signed, per-coefficient prior penalty on the perturbation LASSO, or drop `prior_lasso` from the public list until it is that. Export edges as `(regulator=column, target=row, sign, weight)` for GeneSPIDER matrices. Make `--directed` a no-op on methods that already return a directed \(A\), and do not infer direction from \((I-A)^{-1}\).

**Effort.** Small for the edge-list orientation and for gating `--directed`. Large if Inferelator itself is in scope; a prior-weighted LASSO is medium and is the useful subset for motif priors on K562.

### Performance

**Problem.** NestBoot uses a `ThreadPoolExecutor` over fits, with `threadpoolctl` pinning each fit to one BLAS thread (`src/methods/nestboot.py`). `pinv` releases the GIL, so LSCO does use the cores. sklearn forests and the pure-Python mutual-information loop do not scale the same way. GENIE3 inside NestBoot is one forest per gene per fit, default 100 trees, times `2 * nest_runs * boot_runs`. At the CLI defaults (50×50) and a few hundred genes that is not a run one waits out. TIGRESS is excluded from NestBoot; GENIE3 is not. arboreto is vendored with `n_jobs: 1`.

Memory is a dense cube. `_nested_fdr` can score an edge list (`mask`), but every fit still returns a dense \(N \times N \times n_{\zeta}\) array. At \(N=10^{4}\) and 41 zetas the support counts alone are tens of gigabytes, before the fit. Genome-wide Perturb-seq will not go through this path; a TF-restricted column set would. There is no GPU path. The old MATLAB `BolscoGPU` prototype is not a reason to add one until the CPU algorithm matches.

`joblib` appears in `src/nestboot_eval.py` as a script, not in the library.

**Change.** Default NestBoot to processes for methods that hold the GIL, and keep threads for LSCO. Refuse or downsample GENIE3-in-NestBoot unless the user passes a small tree count. For large \(N\), fit only TF columns and pass the edge mask `_nested_fdr` already accepts. That is the scalable version of a biological GRN: regulators are a few thousand TFs, targets are many.

**Effort.** Medium. The TF-column restriction pays off more than a GPU port.

## Low

### Packaging, imports, seeding

**Problem.** `docs/site/versioning.md` promises `from pyGS import NetworkBootstrap` and `from pyGS.bio import ...`. The wheel lists `src/analyze`, `src/bench`, `src/bio`, `src/bootstrap`, `src/datastruct`, `src/methods` (`pyproject.toml`), so the import names are those top-level packages. `src/__init__.py` documents a `pyGS` package and imports `bootstrap.nb_fdr` and `integration`, which are not in the tree (`src/bootstrap/` has no `nb_fdr.py`). `requires-python` is `>=3.12`; `.github/workflows/ci.yml` still matrices 3.10 and 3.11 and installs a `sparselink/` checkout that is not in this tree. The CI agent owns the workflow. The import story is separate: a user who follows the versioning page does not get the library.

`sparselink` is unpinned in `pyproject.toml` (the lockfile pins it only for `uv`). Algorithmic changes in a future sparselink release change GENIE3’s orientation and LASSO’s default alpha without a pyGS diff.

`run_nestboot` calls `np.random.seed(seed)` and then uses the global generator. Draws happen before the pool, so the bootstrap indices are reproducible. Methods that draw inside a fit (TIGRESS, GENIE3’s forest, even with `random_state=42` shared across every bootstrap) are not independent streams. Dataset names include `datetime.now()` (`src/datastruct/Dataset.py`), so two runs of the same matrix do not get the same id.

Type hints: mypy is strict on the scientific packages, and the public `src/__init__.py` is untyped and points at missing modules. Several bootstrap modules are excluded from ruff F821 rather than fixed.

**Change.** Either install an actual `pyGS` package that re-exports `bio`, `methods`, and `Nestboot`, or change the versioning page to the imports that work. Pin `sparselink` to the version whose orientation and LSCO you have tested. Replace the global seed with one `numpy` Generator passed into the sampler. The CI Python matrix is the other agent’s job; the missing `pyGS` package is this one.

**Effort.** Small. Do it before calling the API stable at 1.0.0. The version is already 1.0.0 while items 1–3 are open, which is the reproducibility risk, not the version number itself.

### Network properties

**Problem.** `Model._calc_time_constant` (`src/analyze/Model.py`) takes eigenvalues of \(G = -A^{+}\) and returns \(\min 1/|\mathrm{Re}\,\lambda(G)|\). For \(\dot x = Ax\) the time constants are \(1/|\mathrm{Re}\,\lambda(A)|\). Because \(\lambda(G) = -1/\lambda(A)\), this returns \(|\lambda(A)|\) rather than the time constant. Interampatteness is `cond(A)`, which matches the toolbox’s definition of IAA as the condition number. Clustering and path length are diagnostic only.

**Change.** Use the eigenvalues of \(A\). Low priority next to the inference errors.

**Effort.** Small.
